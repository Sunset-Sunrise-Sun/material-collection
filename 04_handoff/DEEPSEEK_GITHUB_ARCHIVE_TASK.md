# DeepSeek 执行指令：把材料归档并 push 到 GitHub

目标仓库： https://github.com/Sunset-Sunrise-Sun/material-collection.git

请在有权限的本地工作区执行，先检查当前仓库与工作区，不能假定文件都在本地。

## 步骤

1. 读取仓库根目录的 `README.md`、`00_project/ARCHIVE_STATUS.md`、`00_project/MATERIAL_MANIFEST.md`。
2. 检查本地是否能访问 Library 导出的材料或用户的研究工作目录。如果缺少原件，列出缺失清单并向用户索取/请求下载；禁止按文件名伪造或重新生成原始 PDF/DOCX/XLSX/ZIP。
3. 将已列出的原始文件按以下目录分类，保留原文件名：
   - `01_official_evidence/`：官方检索记录、证据台账、官方来源附件与取证工作表。
   - `02_scenario_and_evaluation/`：场景与评价总表、冻结指标框架、需求判据、最终报告。
   - `03_gis_and_data/`：GIS 输入/输出、数据清单、检查脚本、数据口径对账及联合归档包。
   - `04_handoff/`：交接 Markdown 与 DeepSeek 提示词。
   - `05_deliverables/`：阶段报告、最终报告、ZIP 成果包；历史版本放 `05_deliverables/history/`。
4. 首先上传 2026-10-17 最新官方取证第二轮归档和台账；其次上传 2026-10-16 最终交付报告、场景总表与最终成果包；然后上传历史包。历史原件不能覆盖最新原件。
5. 对每个文件记录 SHA-256、字节数、原始路径、归档路径、版本日期和状态；对 ZIP 执行完整性检查并导出内部文件清单。
6. 做字节级重复检测。重复件可保留一份原件并在清单中记录重复文件名和哈希；如果无法确认字节完全相同，则分别保留。
7. 检查敏感信息和凭证；不要提交密码、访问令牌、个人身份信息或无关隐私。不得为了方便而将私密原始数据公开。
8. `git status`、查看差异、确认目录和文件名后提交。提交信息使用清晰的归档语义，例如 `archive: add eldercare research source materials`。
9. push 到 `main`。如果远端分支已有新提交，先 fetch/rebase 或 merge，不得 force push。
10. 完成后输出：commit SHA、已推送文件数与总大小、目录树、SHA256 清单、ZIP 完整性结果、重复件清单、未上传文件及原因。不要声称未完成的校验已经通过。

## 研究约束

- 冻结的 7 维 16 项指标（A1—G2）不得修改。
- 不把政策目标写成已完成，不把智慧养老自动写成 AI，不把服务量写成 AI 效果。
- 不把全市汇总需求数据人为分配到街镇；缺乏街镇需求数据时不生成需求热点/供需匹配结论。
- 官方统计“独居老年人数 1.52 万”与“其中孤寡老人数 1.55 万”的口径异常须保留并标待核，不自行修正。
